# Request a Feature

Use this guide for:
- new capabilities
- workflow improvements
- documentation or tooling enhancements
- backlog ideas not yet committed to active work

## What to Include

1. Short feature summary.
2. Problem being solved.
3. Expected user or maintainer value.
4. Constraints or non-goals.
5. Related docs, tickets, or prior analysis.

## Initial Classification

- If the request is near-term and plausible, route it to `doc/planning/backlog/future/candidates/`.
- If the request needs discovery first, route it to `doc/planning/backlog/future/research-needed/`.
- If the request is intentionally parked, route it to `doc/planning/backlog/future/icebox/` and include the required icebox metadata.

## Promotion Rule

Move a feature request into active planning only when:
- scope is clear enough to decompose into tickets
- dependencies are understood
- a maintainer agrees it is committed work
