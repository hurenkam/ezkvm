<objective>

Complete the `start` verb so it satisfies VMGR-01 and VMGR-02 in full: bring up `swtpm` (when TPM is configured) with a real readiness poll instead of a fixed sleep, guard against double-starting an already-running VM, clean up an orphaned `swtpm` if qemu itself fails to spawn, and automatically launch the correct UI client after qemu is up. This plan extends the tracer's `start()` in place — it does not touch the CLI surface or `main.rs` at all, so it can execute in parallel with `08-03` (QMP client + stop/kill/reset), which is the other wave-2 plan built on the same `08-01` tracer.

Purpose: Fulfil D-10, D-11 through D-15, D-17 — the "start" verb's complete happy-path and failure-path behavior, beyond the tracer's TPM-less minimal case.

Output: `ezkvm start <vm-name>` works correctly for TPM-configured VMs, rejects double-starts, cleans up orphaned swtpm on qemu failure, and launches the right UI client (or none) automatically.

**Test independence note:** Consistent with `08-01`, none of this plan's tests spawn a real `swtpm`/`remote-viewer`/`looking-glass-client` binary. This plan adds `src/bin/fake_swtpm.rs` (a `UnixListener`-based stand-in for `swtpm socket --ctrl type=unixio,path=...`) and `src/bin/fake_ui_client.rs` (a trivial long-lived stand-in for any UI client binary), both referenced by tests via `env!("CARGO_BIN_EXE_fake_swtpm")`/`env!("CARGO_BIN_EXE_fake_ui_client")` and configured as `HostConfig.swtpm_path`/`HostConfig.remote_viewer_path`/`HostConfig.looking_glass_client_path`. `08-01`'s `fake_qemu` stub is reused unchanged for the qemu side of every test in this plan.

</objective>

<behavior>

- **Test 1:** `wait_for_socket(path, Duration::from_secs(5))` against a path that becomes connectable 200ms after a background thread creates a `UnixListener` there returns `Ok(())` well before the 5s timeout.
- **Test 2:** `wait_for_socket(path, Duration::from_millis(200))` against a path that never becomes connectable returns `Err(ReadinessError::Timeout { .. })` at approximately the requested timeout (within a generous tolerance for test-environment scheduling jitter).
- **Test 3:** Starting a TPM-configured test VM (add a `TpmState` root device to the test fixture's `Runtime`), with `HostConfig.swtpm_path` set to `env!("CARGO_BIN_EXE_fake_swtpm")`, spawns the compiled `fake_swtpm` stub as `fake_swtpm --ctrl type=unixio,path=<tpm_socket_path>` (the stub parses this argument shape identically to real `swtpm`), waits for its socket, then spawns `fake_qemu` (from `08-01`) with the matching `-chardev socket,id=tpmchar,path=<tpm_socket_path>` flag already emitted by Phase 7; the test confirms both PIDs are alive and recorded in the `VmHandle` (`swtpm_pid` is `Some`).
- **Test 4:** Calling `start()` a second time for a VM whose `VmHandle` state file records a still-alive `fake_qemu` PID (from Test 3, before teardown) returns an `AlreadyRunning` error and does not spawn a second qemu process.
- **Test 5:** Simulating a qemu spawn failure (e.g. point `qemu_path` at a nonexistent binary in the test's `HostConfig`) after `fake_swtpm` has already started successfully results in: the `fake_swtpm` process no longer being alive (killed), and `VmHandle::read()` returning `None` (state file removed) — no orphaned swtpm process survives the failed `start()` call.

</behavior>

<action>

- Create `src/bin/fake_swtpm.rs` — a new Cargo `[[bin]]` target, a minimal, host-independent stand-in for `swtpm socket --ctrl type=unixio,path=...`, used only by this phase's tests:
  - Parses its `std::env::args()` for a `path=<socket_path>` component (mirroring real swtpm's `--ctrl type=unixio,path=<socket_path>` argument shape, so production code needs no test-specific branching).
  - Binds a `UnixListener` at `<socket_path>` and accepts connections in a loop (no protocol handling needed — `wait_for_socket`'s readiness check only requires the socket to accept a TCP-style connect, not exchange any data).
  - Runs until terminated by a signal (`SIGTERM`/`SIGKILL`), matching real `swtpm`'s long-lived-process behavior — this is what makes it killable via `process::terminate_pid` in the D-17 orphan-cleanup test (Test 5).
  - Tests reference the compiled path via `env!("CARGO_BIN_EXE_fake_swtpm")` and set it as `HostConfig.swtpm_path`.

- Create `src/lifecycle/readiness.rs` with `wait_for_socket(path: &str, timeout: Duration) -> Result<(), ReadinessError>` exactly per `08-RESEARCH.md`'s Pattern 3 (50ms poll interval, `UnixStream::connect` attempt each iteration).

- Extend `src/lifecycle/start.rs`'s `start()` function (created as a TPM-less minimal path in 08-01) with, in this order:
  - **D-10 guard, first:** read the existing `VmHandle` (if any) for `vm_name`; if present and `!is_stale()`, return `StartError::AlreadyRunning` immediately, before touching any process.
  - **TPM branch:** if the loaded `Runtime` contains a `TpmState` root device, compute a `tpm_socket_path` under `state_dir` (e.g. `<state_dir>/<vm_name>.tpm.sock`), spawn `swtpm socket --ctrl type=unixio,path=<tpm_socket_path>` via `process::spawn_detached`, then call `readiness::wait_for_socket(tpm_socket_path, Duration::from_secs(8))` (8s, per `08-RESEARCH.md`'s Open-Questions recommendation of 5-10s) — on timeout, kill the swtpm process and return `StartError::SwtpmNotReady` without ever spawning qemu.
  - Pass the computed `tpm_socket_path` into `QemuContext::new(...)` (previously always `None` in 08-01's minimal path) so Phase 7's TpmState handler emits the matching `-chardev socket` flag.
  - **qemu spawn with orphan cleanup:** wrap the qemu `spawn_detached` call; on `Err`, if a swtpm process was started in this same `start()` call, call `process::terminate_pid(swtpm_pid, true)` and `VmHandle::remove(state_dir, vm_name)` (in case a partial state file was already written), then propagate the original spawn error as `StartError::QemuSpawnFailed` — this is D-17 in full.
  - Record `swtpm_pid: Some(pid)` in the `VmHandle` written at the end of a successful start (was hardcoded `None` in 08-01's minimal case).

- Add `StartError::AlreadyRunning`, `StartError::SwtpmNotReady`, `StartError::QemuSpawnFailed` variants (`thiserror`) to whatever error enum 08-01's `start.rs` defined.

</action>
