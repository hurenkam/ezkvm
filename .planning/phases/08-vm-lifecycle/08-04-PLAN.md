<read_first>

- `08-02`'s additions to `tests/vm_lifecycle.rs` — the TPM-configured test fixture and `08-02`'s `src/bin/fake_swtpm.rs`/`src/bin/fake_ui_client.rs` stub binaries (`env!("CARGO_BIN_EXE_fake_swtpm")`/`env!("CARGO_BIN_EXE_fake_ui_client")`), standing in for `swtpm` and `remote-viewer`/`looking-glass-client` respectively.
- `08-03`'s `lifecycle::stop::stop()` — reads `VmHandle::ui_client_pid()` and terminates it on success.

</read_first>

<behavior>

- **Test 1 (`test_full_lifecycle_start_and_stop`):** Build a `Runtime` with a `TpmState` device and a `Spice` display; `start()` it against a `HostConfig` whose `qemu_path`/`swtpm_path`/`remote_viewer_path` point at the compiled `fake_qemu`/`fake_swtpm`/`fake_ui_client` stub binaries; assert (after the ~1-2s UI-client delay) that `VmHandle::read()` shows all three PIDs (`qemu_pid`, `swtpm_pid`, `ui_client_pid`) as `Some` and alive; call `stop()`; assert all three PIDs are no longer alive and `VmHandle::read()` returns `None`.
- **Test 2 (`test_qemu_failure_kills_orphaned_swtpm_with_full_config`):** Repeat `08-02`'s orphan-cleanup test (Task 1's Test 5) but against a `HostConfig` that also has a valid `remote_viewer_path`/`looking_glass_client_path` configured (i.e. the full config shape, not a minimal stub) to confirm the orphan-cleanup path isn't accidentally dependent on those fields being absent.
- **Test 3 (`test_start_already_running_fails_with_full_lifecycle`):** After Test 1's VM is started (before `stop()`), attempt a second `start()` call for the same `vm_name` and assert `StartError::AlreadyRunning`; then proceed to `stop()` and confirm the *original* PIDs (not a second set) are what get cleaned up.

</behavior>

<action>

- Add `test_full_lifecycle_start_and_stop`, `test_qemu_failure_kills_orphaned_swtpm_with_full_config`, and `test_start_already_running_fails_with_full_lifecycle` to `tests/vm_lifecycle.rs`, reusing existing fixtures/helpers from `08-01`/`08-02` rather than redefining them.
- If any test reveals a genuine integration bug at the seam between `08-02`'s start-flow additions and `08-03`'s stop implementation (e.g. `VmHandle` field name mismatch, ordering issue), fix it in the smallest possible diff to the already-existing `lifecycle::*` modules — do not introduce new modules or new must-have behaviors in this plan.

</action>
