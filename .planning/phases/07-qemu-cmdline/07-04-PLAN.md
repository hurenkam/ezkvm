<action>

- Create `src/config/qemu/bootindex.rs` with four pure label-reconstruction functions per RESEARCH.md's Critical Gap mapping table:

  ```rust
  pub(crate) fn scsi_label(target: u8) -> String {
      format!("scsi{}", target)
  }
  ```

  - Assumes `lun == 0`, documented in a comment as true for all Proxmox single-disk-per-target usage per RESEARCH.md.

  ```rust
  pub(crate) fn ide_label(channel: u8, device: u8) -> String {
      format!("ide{}", channel * 2 + device)
  }
  ```

  - Confirmed formula, felucia `ide2` example in the doc comment.

  ```rust
  pub(crate) fn sata_label(port: u8) -> String {
      format!("sata{}", port)
  }
  ```

  - Comment: `// [ASSUMED] — not present in the felucia sample, follows scsi/ide {bus}{index} convention per RESEARCH.md Assumption A2`

  ```rust
  pub(crate) fn net_label(ordinal: u8) -> String {
      format!("net{}", ordinal)
  }
  ```

  - Comment: `// [ASSUMED] — ordinal = position among VirtioNetPcie entries sorted by PcieAddress; only one NIC in the only available corpus file, per RESEARCH.md Assumption A1`
- Add:

  ```rust
  pub(crate) fn lookup_bootindex(boot_order: &[String], label: &str) -> Option<u32> {
      boot_order
          .iter()
          .position(|entry| entry == label)
          .map(|pos| 100 + pos as u32)
  }
  ```

  - `.position()` returns `None` when absent, which the `Option` return type already models correctly; no special-casing needed.
- In `src/config/qemu.rs`, add `mod bootindex;` to the module declarations (alongside the existing `mod builder;` / `mod handlers;` from Plan 07-01).

</action>
