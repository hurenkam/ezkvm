<objective>
Replace the untyped `UsbDeviceKind::HostPassthrough { resource: String }` — parsed only at QEMU-emit
time via a panicking `.expect()` — with a typed `UsbHostIdentity` enum (`BusPort{bus,port}` vs
`VendorProduct{vendor_id,product_id}`) parsed once at the Proxmox-import boundary, per D-01. Fixes
the real production bug found in Phase 9 research: `usbN: host=0451:16a0` (vendor:product-ID form,
present in zbp-server-mh2/301.conf) panics today because the emitter assumes every `host=` value is
`<bus>-<port>`.

This plan touches all 5 conversion layers the research identified (not just the 4 named in
CONTEXT.md): Runtime type (`usb_generic.rs`), ezkvm YAML schema (`schema/usb.rs`), Proxmox importer
(`importer.rs`), QEMU emitter (`handlers/usb.rs`), AND the Runtime<->YAML conversion layer
(`runtime/parser.rs`, `runtime/builder.rs`) plus the `Display`-formatting dispatch in `runtime/q35.rs`
— Rust's exhaustive-match compiler enforces all of these once the enum shape changes (Pitfall 1).

Purpose: Satisfy RUNT-10 — USB host-passthrough identity round-trips losslessly through Proxmox
import, ezkvm YAML, and QEMU commandline emission, for both real-world identity forms.
Output: Typed `UsbHostIdentity` used end-to-end; zero `.expect()`-panic risk on malformed/varied
`host=` values; existing bus-port tests updated, new vendor:product-ID tests added.

Scope note: per D-04, no backward-compatibility shim is needed for existing ezkvm YAML files whose
`HostPassthrough { resource: String }` shape changes here — free to change the on-disk YAML shape.
Per D-05/D-06, this plan does NOT touch RawArgs smart re-injection (deferred, out of scope) and does
NOT add Phase 9-style four-stage round-trip integration tests (Phase 9's own responsibility) — only
unit/structural-level tests (schema round trip, importer mapping, emitter output) per D-06.
</objective>
