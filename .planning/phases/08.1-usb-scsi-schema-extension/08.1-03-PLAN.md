<objective>
Model `virtio-scsi-single` as a genuinely separate Runtime device type — a PCIe device that directly
implements the storage-device trait(s) itself (no internal `scsi_bus`), per D-03 (LOCKED). Proxmox
creates one dedicated virtio-scsi controller instance *per disk* under this mode (for iothread/
performance isolation), unlike `pvscsi`/`virtio-scsi-pci`'s single shared-bus controller (Plan
08.1-02). Real corpus data (zbp-server-mh2/301.conf) has 4 `scsiN` disks all under one
`scsihw: virtio-scsi-single` declaration — 4 separate merged-device instances in one VM.

This directly fixes Research Pitfall 2: today's `emit_pvscsi`/`emit_scsi_storage` hardcode
`id=scsihw0`/`drive-scsi{target}` assuming exactly one controller instance ever exists in a VM. Under
this plan, N merged-device instances must produce N distinct, non-colliding QEMU `-device`/`-drive`
`id=` tokens — this plan adds an explicit controller-id parameter (keyed on the Proxmox `scsiN` index,
per D-08) to the emitter functions rather than leaving a hardcoded literal.

Depends on Plan 08.1-02 (wave 2) — both plans touch the same conversion-layer files
(`importer.rs`, `handlers/pcie.rs`, `handlers/storage.rs`, `runtime/parser.rs`, `runtime/builder.rs`,
`runtime/q35.rs`); Plan 08.1-02 must land the `ScsiControllerType`/`GenericScsiController` rename
first so this plan's new `VirtioScsiSingleDisk` type sits alongside a stable renamed foundation.

Per D-03 (LOCKED): do NOT add a third `ScsiControllerType` variant for `virtio-scsi-single` — it is
never a shared-bus controller. Per Research Pitfall 3/Open Question 1 (consistent with Plan 08.1-02's
D-07 scope note): `VirtioScsiSingleDisk` gets a `PcieDevice` impl only in this plan (matches every
corpus VM's actual controller placement — Proxmox always uses a PCIe slot); no `PciDevice`/`IsaDevice`
impls are added for this new type — there is no corpus need, and adding them would be unreachable code
this phase would then have to maintain with no test coverage.

Purpose: Completes RUNT-11 — SCSI controller type (`pvscsi`, `virtio-scsi-pci`, `virtio-scsi-single`)
is a first-class Runtime concept for all 3 real-world variants, round-tripping losslessly and emitting
correctly, with zero corpus-observed data loss.
Output: `VirtioScsiSingleDisk` merged device type; `zbp-server-mh2/301.conf`'s 4-disk
`virtio-scsi-single` VM importable and emitting a collision-free QEMU commandline.
</objective>
