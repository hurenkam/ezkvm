<objective>
Create the phase's tracer slice: a single new integration test file, `tests/round_trip_verification.rs`,
that chains all four pipeline stages — `.conf`+`storage.cfg` → `ProxmoxImporter` → `Runtime` →
`EzkvmConfigSchema` (YAML) → `Runtime` → `QemuCommandLine` — in one pass for `input/felucia/108.conf`,
per QEMU-04 and `09-CONTEXT.md` D-04/D-05. This is genuinely new work: no existing test chains all
four stages together (Phase 6's `yaml_round_trip.rs` and Phase 7's `qemu_cmdline.rs` each only
exercise two adjacent stages). This plan establishes the `load_corpus()`/`runtime_for_cmdline()`
helper pattern that Plan 09-03 reuses verbatim for coruscant/501 and zbp-server-mh2/301.

Purpose: Prove the full round-trip pipeline works end-to-end on real corpus data, on the felucia
fixture that has no blocking bugs (zbp-server-mh2/301's USB vendor:product-ID passthrough is
already fixed by Phase 8.1's typed `UsbHostIdentity`, so Plan 09-03 can rely on it directly),
before expanding to the other two corpus files.
Output: `tests/round_trip_verification.rs` with one passing `#[test]` for felucia/108, plus reusable
`load_corpus()` and `runtime_for_cmdline()` helpers Plan 09-03 will extend in the same file.
</objective>
